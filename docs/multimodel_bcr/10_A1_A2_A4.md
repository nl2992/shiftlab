# BCR: A1 adapter audit, A2 matched-label control, A4 recovery fixes (three-track TODO)

## A1: active model-selection SOTA, fidelity and applicability

| Method | Repo implementation | Native problem | Fits our contract (delayed labels, hard budget, switch cost)? | Used as |
|---|---|---|---|---|
| Model Picker (Karimi et al., AISTATS 2021) | `competitors/model_picker.py`: line-referenced port of the author code (native class + deployment adapter, deviations marked `# ADAPTER`) | stream best-model identification, immediate labels, no switch cost | query rule yes (IPW with frozen propensity); deployment needs an adapter (argmin estimated loss) | B3 adapter; B4 acquisition + Wald deployment |
| Model Selector | `competitors/model_selector.py`: native pool algorithm plus a causal adapter | pool-based: label any past unlabeled example | **no**: the simulator can only label the current event; the pool rule is not representable without changing the observation contract | excluded (reason in its docstring) |
| CAMS (Liu et al., NeurIPS 2024) | `competitors/cams.py`: port of author code | contextual active model selection over a set of advice policies | partly: the author's trained advice policies are not shipped (BLOCKED in the port) | represented by the tabular analogue `cmp` (per-context MP + Wald) in the contextual study (09) |
| Variance-minimising AMS (Hara et al., 2024) | `competitors/variance_min.py`: port of author code (query score Eq. 8, LURE estimator) | pool sampling for risk-estimation variance | query score usable on stream events; not run in the BCR pilot | not run (gap recorded) |
| Consensus-based active model selection | none in repo | — | — | not implemented (gap recorded) |

All comparator gains are therefore against **adapters** of Model Picker (and a tabular CAMS
analogue), never against native published systems.

## A2: matched label-count control (frontier data, 20 seeds)

Disagreement-paced K-Wald at B=100 (≈100 labels) vs Model-Picker acquisition + Wald at B=200
(≈95 labels):

| c_q | MP + Wald − disagreement Wald (matched labels) | economic MP (labels) |
|---|---|---|
| .02 | −1.77 [−5.11, +1.56] | 554.8 (83) |
| .05 | −1.91 [−5.26, +1.43] | 557.3 (83) |
| .10 | −2.15 [−5.51, +1.21] | 561.4 (83) |
| .20 | −2.62 [−6.01, +0.77] | 569.4 (59) |

At equal label counts MP-style acquisition is consistently, but not significantly, ≈2 units
better. It is a real but small label-efficiency effect, and it belongs to Model Picker's query
rule, not to BCR.

Recovery fixes bring BCR's label use back to ordinary pacing levels without closing the
reversal gap (E3: 556.9 best vs 545.3).

## Track A verdict: **STOP**

No novel ranking or acquisition mechanism improves on the strongest applicable baseline.
- The only effects found (label efficiency at matched cost, a high-price edge for economic MP)
  belong to Model Picker's query rule.
- Those effects are small: ≈2 units, about 0.3–0.5% of cost.
- Specialist structure is handled by standard contextual routing.
