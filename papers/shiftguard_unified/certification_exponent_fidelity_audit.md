# Q2 source and task-fit audit: *The Certification Exponent*

**Audit date:** 2026-10-26  
**Primary source:** Rui Wang, “The Certification Exponent: Instance-Optimal Sequential Certification of Policy Improvement from History Dependent Logs,” arXiv:2610.24345v1, submitted 2026-10-17 and marked as submitted to JMLR. This is a preprint, not a peer-reviewed publication. [Primary arXiv record](https://arxiv.org/abs/2610.24345).

## Result of source review

The paper studies a fixed target policy versus a known logging policy on sequential logged episodes. The logger may depend on history. The environment class is restricted by the logged action conditionals, rewards are bounded, and soundness is uniform over environments in that class. Its null is that the target policy does not improve on the logger. The target is a one-sided policy-improvement certificate; it is distinct from ShiftLab's common-label classification-cost comparisons, temporal paired-harm monitoring, and Molitor's finite-class optimal-policy identification.

The paper defines an instance-dependent certification exponent `K*` as the minimum KL divergence from the observed logged law to an admissible null logged law. For a `delta`-sound sequential certifier it gives the expected sample lower bound `E_P[tau_delta] >= log(1/delta)/K*`; under `0 < K* < infinity`, its predictable plug-in Kelly construction matches the exponent asymptotically as `delta` tends to zero. Its coverage analysis distinguishes impossible certification (`K*=0`), finite-rate certification, and an arbitrage/dominance regime. The paper also gives a scalable “cushion” construction for trees too large to enumerate. These results make generic novelty claims for sequential candidate-versus-incumbent policy certification untenable.

The paper's experiment section says code and raw outputs are in supplementary material. The public arXiv source archive downloaded for this audit was 1,228,289 bytes, SHA-256 `ae05d1fa7bf09fc771af6a1a07f70d342fd2e6ebdd7654e133aaea9b44fd707c`. Its complete file listing contains the LaTeX source, bibliography, style file, and figures only; no implementation or separate supplement is present. No public code repository or supplementary package was located in the bounded source search. Accordingly, this is a primary-paper and task-fit audit, not an implementation review or reproduction.

## Fit to ShiftLab

The result is a high-priority Q2 comparator for logged-policy improvement. A one-step contextual-bandit specialization is plausible for the frozen OBD item-41 question, where the target candidate is fixed and logged propensities are available. That does **not** yet establish eligibility: the OBD replay's user/slate dependence, effective decision unit, context-as-of semantics, reward-release timing, and independence assumptions remain unresolved. The common-label candidate-selection experiments are not direct matches because one outcome reveals multiple candidate losses, unlike action-dependent logged feedback.

The closest fair development comparison would use matched one-step logged contextual streams and compare the paper's implementation or a faithful specialization with MOPE's fixed-candidate gate and the existing fixed-horizon Hoeffding control. The same contexts, logger propensities, target candidate, bounded rewards, seeds, and horizons must be used. Report null false-certification, power/promotion, expected events to certificate, empty or nonterminating paths, computational cost, and support/coverage failures separately. Do not compare its sample-efficiency exponent with shared-label Target-Scout as if the observation models matched.

## Decision and remaining action

This source narrows the Q2 contribution and reopens the logged-policy comparator gate. Before claiming the Q2 frontier is complete, obtain and inspect the claimed supplement or implement a clearly labeled one-step specialization from the paper after documenting every assumption and proving numerical equivalence on small enumerated trees. Then run a prespecified matched comparison if assumptions can be satisfied. If no usable supplementary code is accessible and an exact, testable specialization cannot be derived, record that reason and its impact on the paper's claims; do not silently omit it.

### One-step implementation and matched-run status (2026-10-27)

No public supplement or author code was found in the audited source archive. A labeled context-free two-arm, binary-reward specialization is now implemented in `src/shiftlab/dive/certification_exponent_one_step.py`; its frozen estimand, logger, null, warm-up deviation, refit schedule, feedback contract and comparison are specified in `certification_exponent_one_step_protocol_v1.md`. Nine focused tests pass, including full-four-leaf bet feasibility, the null conditional-mean inequality, predictable refitting and a grid check of the plug-in optimizer. This checks the restricted implementation, not the paper's full multi-step-tree algorithm or its asymptotic exponent theorem.

The preregistered 1,000-null / 300-alternative comparison uses the unmodified MOPE reference at commit `a4b8584b622f3a8296932568c520c1bb3e1957f0`, alongside the one-step method and a fixed-horizon Hoeffding gate. GPU generates the matched streams; the source-pinned MOPE path runs on CPU. The long-running job has not yet produced artifacts, so no comparative metric is available. An attempted reuse of ShiftLab's exact 2-D QP optimizer at `wmax=2` matched the per-event QP objectives to `3.11e-11` maximum difference but failed confidence-path reproduction (maximum bound difference `0.1494149`, with no empty-set classification mismatches in the four 75-event checks). Because the MOPE confidence path is the benchmark output, this optimizer is **not** substituted for the pinned solver in the registered run. The OBD data remain outside the method's validity claim.
