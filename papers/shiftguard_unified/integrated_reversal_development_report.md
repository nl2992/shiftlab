# Integrated post-promotion reversal development run

**Status:** two-seed CUDA smoke/development run only; not a calibrated or confirmatory result.  
**Protocol:** captured draft v0.2 at execution; the live post-run status is draft v0.3 in [`integrated_benchmark_protocol.md`](integrated_benchmark_protocol.md).  
**Artifacts:** [`pipeline_controller_dev_v3/`](../../outputs/shiftguard_unified/integrated_development/pipeline_controller_dev_v3/).

The seven-policy development grid ran two seeds across seven profiles, producing 98 matched policy-stream rows on the RTX 4060. The new `post_promotion_reversal` profile uses the harmful-adaptation process through event 2,399, then makes the frozen all-positive incumbent optimal from event 2,400 onward. The outcome change is scheduled before policy actions are evaluated and does not depend on the selected candidate. The profile is a synthetic stress test, not a real-data model or deployment claim.

On seed `2026102701`, two-gate certification promoted the selected candidate. Both the two-gate and full-pipeline arms crossed the rollback threshold at event 2,538, after 138 deployment events and 21 queried labels. The final log e-value was 4.373 against a threshold of 4.200. The controller-gated arms made the same decision on this seed. The candidate caused −320.10 realized incremental utility before fallback; the evidence-triggered rollback did not erase harm already incurred. On seed `2026102700`, no candidate was promoted, so no rollback test occurred. Thus this grid demonstrates that the rollback path is reachable, while also exposing meaningful delay and cumulative harm; it estimates neither rollback power nor its false-alarm rate.

The Q1-triggered fallback and unconditional scheduled-promotion controls had mean realized incremental utilities of −1,301.05 and −1,652.55 in this two-seed reversal cell. These unstable two-stream averages are included only to show the stress profile's direction and must not be treated as comparative evidence. The controller did not improve over the certificate-only workflow in these two seeds. Across all 98 rows, the maximum label use was 632/640.

Future-only outcome timing is covered by a regression test that verifies the Q1 trigger, candidate identity, promotion decision, and scout-label count are unchanged when the post-certification reversal is added. The same test verifies that the reversal can create a rollback crossing. Focused tests, Ruff, mypy, protocol/source snapshot hashes, and all three output hashes passed. Exact input sources are copied under `execution_sources/`; the current protocol snapshot is `protocol_snapshot.md`. The earlier relative-path failure remains preserved in `pipeline_controller_dev_v1/` for audit.

This smoke result does not validate the proposed familywise alpha allocation, establish any error rate, or support a superiority claim. The development seeds overlap the earlier pilot. Before confirmation, the next gate is a fresh, frozen simultaneous null calibration of escalation, promotion, and rollback errors, with enough independent streams to bound the familywise rate; confirmation must use a separate seed block. The broader baseline gap, including applicable published resource-allocation/retraining methods, remains open.
