# Confirmation protocol status

**Status: NOT FROZEN; no confirmatory run authorized by this research package.** This is the
pre-outcome rule for the current execution. The bounded rollback/acquisition pilot is development
only. No candidate may be promoted to confirmation unless the pilot establishes a non-separable
benefit beyond ordinary E_rb tuning, two-sided SR/CUSUM, fixed reserve, or front-loaded acquisition
and the prior-art review supports a distinct claim.

No held-out dataset or confirmation outcome has been opened. In particular, OPSD and Binance
holdouts remain locked under the lane-B handoff; Wild-Time candidate outcomes were not used to tune a
method. No confirmatory claim can be reconstructed retroactively from the already exposed Failure
Atlas, Sprint 2, corrected replays, or the development pilot.

If a distinct method survives the development gate, a separate prospectively dated protocol must
freeze: method/version and code hash; claim and applicability region; strongest published comparator
set and source/code versions; T, pathwise budget, pending-label accounting, delay, label and switch
costs; observable information; thresholds and tuning split; primary outcome and paired statistic;
independent seed generation; null and adverse-regime checks; real dataset/source registry,
chronology and source clusters; one-opening runner and checksums; stopping rule; and exclusions.
Until that artifact exists and is reviewed, the confirmation status remains closed.
