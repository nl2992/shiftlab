# T0.2: independent E1 verification

Status: every claimed value recomputes within its tolerance. There is no numerical mismatch. One
scope caveat on the WP4 "68/68" wording and two limits on independence are recorded below. This
is a re-verification of frozen artifacts (descriptive/development evidence), not new evidence.

## Command

```
uv run --no-sync python scripts/stage0_e1_verify.py
```

CPU only, about a minute. It writes `docs/research_refinement_v1/stage0/e1_verification.json`
and exits non-zero on any FAIL, MISSING or hash MISMATCH. Result of the committed-state run:
63 checks, 62 PASS, 0 FAIL, 0 MISSING, 1 INFO; 32 hash comparisons, all MATCH.

The verifier imports only numpy, pandas, pyarrow and scipy; it does not import `shiftlab` or any
analysis script. I read `scripts/analyze_gated_monitor_comparison.py` only to learn column
semantics and the recorded bootstrap procedure (seed 20261027, B = 10,000). Summary and
decision files are read only after recomputation, to compare.

Tolerance is half a unit in the last reported digit (e.g. 7.2014 -> 5e-5; 17.47 -> 0.005;
7.9e-31 -> 5e-33; 118.1 -> 0.05; 0.86 -> 0.005), except where noted.

## Mismatches and diagnoses

No claimed number fails. Items a reader should know:

1. **WP4 "68/68" applies to the primary epsilon = 0.1 rows only (definition scope).**
   `null_cells.csv` has 136 rows (68 per epsilon). The `README.md` row description says
   "primary and `epsilon = 0`", and the claim matrix K8 says "68/68 per-path orientation cells".
   Only epsilon = 0.1 has 0/1000 in every cell. At epsilon = 0, 53/68 cells are at 0 alarms; the
   total is 265 alarms and the maximum cell is 28/1000 (gated_ht_paced), with cp upper bounds up
   to 3.82%. That is consistent with `docs/eia_real_data_validity_results.md`, which labels
   epsilon = 0 "descriptive, null boundary" and not as the registered pass/fail. The claim stands as
   worded in K8 but should say "primary epsilon = 0.1" to prevent misreading 136 rows as 68/68.
   Recorded as INFO, not FAIL. The 0.72% all-cell bound is valid for the 68 primary cells only
   (136 cells would give 0.79%).
2. **Seed-block text error (known, T0.4).** `docs/gated_monitor_null_calibration_results.md`
   states seeds 58300000-58301999; the frozen parquet and the analysis guard have
   58500000-58501999. The parquet is authoritative and matches the matrix K8 wording.
3. **Rounding only.** Dollar spend 177.2888 / 170.8659 round to the claimed 177.3 / 170.9;
   H2 r=0.20 shows 7.20 in the table against 7.2014 for H1 (same quantity).
4. **Claimed H4 gain is the expected (oracle) net gain, not realised.** For q1_fallback the stored
   `realized_deployment_gain` is 273.39 / 277.43 / 273.39 / -1,556.35 and the
   `realized_incremental_utility` is 664.47 / 683.81 / 451.23 / -1,149.97. The claims use the
   expected columns (664.64 etc.), which are the summary-CSV `mean_expected_gain`. This is a
   definition choice, not an error, but the metric name should be stated wherever the numbers
   are quoted. (Not verified here: realised-versus-expected sampling noise.)

## Independence limits

- H1/H2 rest on the stored per-stream growth columns (`growth_vs_uniform_ppi`,
  `comparator_growth_uniform_ppi`). The underlying e-process wealth paths are not stored, so the
  best-fixed-stake growth itself cannot be recomputed without rerunning the generator; that is
  outside T0.2 (no reruns). The verification covers aggregation, pairing, bootstrap and tests,
  not the per-stream growth values.
- The bootstrap RNG call (`default_rng(seed).integers(n, size=(B, n))`) must match the original
  to reproduce the CI exactly; the own-seed check (seed 777) is the procedure-level evidence.
- EIA and S2 detection/false-alarm flags are likewise stored outcomes. WP4 `injected.csv` and
  `null_cells.csv` are already aggregated (200/1,000 replicates); their replicate-level data are
  not stored, so only cell-level counts and bounds are checked.
