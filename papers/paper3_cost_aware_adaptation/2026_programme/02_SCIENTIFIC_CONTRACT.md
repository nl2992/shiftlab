# Paper 3 scientific contract v1 (frozen for the core simulator)

Status: contract for `src/shiftlab/paper3/` (core). It defines semantics, not results. No method
here is claimed novel or valid beyond the stated assumptions.

## 1. Filtration and clock

Rounds t = 1..T, a_0 = 0. Two frozen policies with losses ell_t(0), ell_t(1) in [0,1];
Z_t = ell_t(0) - ell_t(1), positive favours the challenger (action 1). The simulator tape holds both
potential losses (shared across all policies of a seed). Order within round t:

1. release every label with `available_time <= t` (never earlier; exactly at t for fixed paths);
2. policy observes `PolicyView`: round index, features x_t, prediction-only disagreement flag,
   the labels released at the start of t, its previous action, remaining/pending label budget;
3. policy chooses (a_t, q_t, u_t, retrain_t) from the view, its own history and private coins;
4. loss ell_t(a_t) incurred; a query is paid and reserved now; its label (both losses) is released at
   the start of t + d_t, integer d_t >= 1.

Filtration H_t = (released labels with request times, features/flags through t, own past decisions
and coins). Decisions are H_t-measurable plus private coins independent of the tape.

## 2. Budget semantics

Label budget B is pathwise and counts pending requests at request time:
`requests_so_far <= B` at all times; labels requested at t with t + d_t > T are paid and never
arrive (pending labels are not free at the horizon). Optional compute budget is enforced the same
way. Exceeding a budget raises `BudgetError` (the loop never silently clips).
Accounting identity: J = deploy_loss + c_q*#queries + k*#switches + c_compute*#compute +
c_retrain*#retrains; `requested = released + pending`. Retraining is cost accounting only in the
core simulator (no effect on losses); this is a stated scope limit.

## 3. Objective

J(pi) = E[ sum_t ell_t(a_t) + c_q sum q_t + k sum 1{a_t != a_{t-1}} + c_compute sum u_t
+ c_retrain N_retrain ]. The simulator reports realised J per (tape, policy) and the decomposition.

## 4. Five separate error notions (never merged)

1. Global-null false promotion: any 0 -> 1 switch on a stream with E[Z_t | H_t] <= 0 for all t
   (evaluator: `global_null_false_promotion`, counted only when the regime has mu_t <= 0 for all t).
2. Current-regime value: time on the wrong side of the true mean (`frac_time_wrong_model`,
   `missed_improvement`, `excess_harm`, `false_promotions` = promotions at rounds with mu_t <= 0).
3. Future payback: promotions whose realised true-mean gain until the next return to action 0 is
   below k (`unpaid_promotions`). Not identified by past data without a drift envelope.
4. Intervention safety: worst cumulative excess realised cost versus never-switch
   (`max_drawdown_vs_never`).
5. Dynamic regret: J minus the hindsight oracle (best at-most-any-switch path on the realised tape).
   **Unattainable diagnostic**; labelled `*_UNATTAINABLE`.

## 5. Assumptions and exclusions

- Exogenous outcomes: actions do not change losses; a queried label identifies both losses.
  No bandit counterfactuals, no off-policy estimation.
- Query decisions depend only on H_t (and independent coins); selective sampling therefore keeps
  conditional-mean statements on queried rounds valid. Informative delays are generated and
  recorded (`delay_log`, regime `informative_delay`) but **no validity is claimed under them**.
- Dependence is generated by an AR(1) Gaussian copula (rho in {0,.5,.8,.95}) with exact
  marginals; the Gate baseline's e-process is valid under the conditional null, not a statement
  about dependent-regime economics.
- Truth (`Truth`: p_t, mu_t, change points) is evaluator-only and is not an argument of
  `run_policy` policies. Features `x` are an observable noisy sentinel, not the regime.
- Out of scope: real data, retraining effects, multi-model candidate sets, learned continuation
  values, CRSP; hindsight and the economic DP are benchmarks, not comparators.

## 6. Seed-range registry (`configs/paper3/seed_registry_v1.json`)

Seeds are SeedSequence entropy integers (tape stream `[seed, crc32(regime), 7]`, policy coins
`[policy_seed, 11]`). Blocks are disjoint and above every block in `configs/seed_registry.yaml`.

| stage | range | rule |
|---|---|---|
| smoke | 5300000000-5300999999 | plumbing, no claims |
| dev | 5301000000-5301999999 | design and tuning (equal documented budgets) |
| model_selection | 5302000000-5302999999 | choosing among frozen candidates |
| confirmation | 5303000000-5303999999 | opened once after freeze |

## 7. Oracle scope (`oracle.py`)

- `EconomicOracle` / `solve_economic`: exact finite-horizon DP (Fractions) for a **known** 2-state
  HMM regime model, Bernoulli paired losses (Z in {-1,0,1}), fixed delay d, budget B, k, c_q.
  Information state (t, a_prev, remaining, released obs, pending request times) is sufficient.
  Validated: equals brute force over **all** deterministic policy trees on T <= 4 instances (tapes
  scored independently by hidden-path enumeration), forward probabilities checked exactly, and the
  DP policy run through `run_policy` reproduces the exact value within Monte Carlo error.
  It is an economic-belief optimum under a known model, **not** a robust global-null-risk oracle;
  it may promote on evidence a risk-constrained rule would reject. Not for model-misspecified
  claims and not tractable beyond roughly T ~ 12, B ~ 3.
- `oracle_risk`: wraps the existing exact sequence-form LP (`shiftlab.dive.causal_switching_game`,
  from research/risk-preserving-switching-approx-2026-10-29@2bd2e8e) for the alpha-safe full causal
  null on its binary-outcome game; its value is not comparable to the paired-HMM DP.
