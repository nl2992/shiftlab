# First substantive development screen — frozen before execution

Run 540 distinct method/world configurations: three tracks, nine method/query
combinations per track, four generator families, five scenarios. This is a
controlled subset of the requested initial 500–1,500 configurations; it does not
exhaust S01–S12 or the mandatory source comparator families.

The exact grid is generated by `scripts/sota_search/run_screen.py:configurations`.
All worlds use horizon 512, stale proxy, severity one, independent geometric delay
of mean three, 20% hard deployment label cap, and 512 labeled source observations.
Within each family/scenario, methods share world, source and query RNG seeds.
Development seeds are 291000–291004; independent source seeds 391000–391004.
Only development/source namespaces are opened. No final confirmation is authorized
by this protocol. The existing one-hour batch and four-hour programme caps apply.

Q1 screen metric: positive conditional decision harm accumulated before alarm.
Report nuisance/stationary alarm diagnostics separately; no matched type-I control
is assumed. Q2: certification by horizon, interpreted alongside instantaneous
nonimprovement diagnostics and source/label cost. Q3: expected cumulative net cost
including label and switch expenditures; report common source cost separately.
All raw per-event trajectories are retained. Fixed global bets and uncalibrated
operating points mean no result may establish SOTA superiority or null validity.

Survival rule for the next development stage: retain the best three variants per
track by mean primary metric over harmful/temporary/cost-only scenarios, after
excluding numerical failures. Q1 minimizes harm, Q2 maximizes certification, Q3
minimizes cost. Also retain every simple parent and frozen comparator regardless
of rank. Preserve a variant showing a strict win on any individual scenario as
a conditional-benefit hypothesis; ties retain all tied variants. Disqualify a
validity claim if its null diagnostics or assumptions fail; retain its raw record.
This is exploratory selection with one seed per scenario, not inferential evidence.

Next-stage tuning must include null calibration, additional independent development
seeds and stronger source-matched alternatives before any initial held-out test.
PPRM random-block/cap-truncation concerns remain unresolved and PPRM is not included
in this first screen. Its required comparison remains outstanding. Mandatory later
full-archive synthesis, targeted cross-parent fixes, ablations and independent
generator-family confirmation remain unchanged.
