# H2c G5 source and comparator contract (partial W03.01/W03.03)

The G5 protocol was committed at `e164d63310cbec7fed4efc16dbf726b20abf0a17` before the result commit `44119c612a0068e21348893fd94a44c20c297b01` in Git ancestry and recorded timestamps. It explicitly names F1 guided discounted cost betting, C1 cost-only discounted betting, C2 cost ONS, and C7a cost SR, the 600-seed cell design, D1-D4 hypotheses, and the per-cell stronger-of-C1/C2 reference. The detector and harness source blobs are byte-identical at protocol and result commits (detector SHA-256 `060d2e45b353e79c829cdd9be4458194082281e29d0b2bcca817334880146e00`; harness `99ab0c117ad7a943e34659a5ebba046357f1f76f09df62e724ff6e6e7c2e0144`). The result-commit parquet, CSV, runner and separate analysis script match their current bytes. However, `scripts/sota_search/g5_confirmation.py` and its analysis script first appear in Git in the **result commit**, not the pre-run protocol commit. The protocol fixes the design; a committed exact executable analysis freeze before exposure is not established by this history. The runner saved the data and then crashed on a DataFrame `shift` name clash; the separate analysis script reads the saved parquet.

The runner maps F1 to `pp_cost_guided(mode="guided_disc", gamma=.995)`, C1 to `fix_cost(gamma=.995, uniform_cap=True)`, and C2 to `pp_cost_guided(mode="cost_ons")`. It passes the same `frac`, delay 5, tolerance 0 and `lseed=95000+k` to every arm in a cell. `_pp_parts` uses `label_mask(sim, frac, lseed)` with the same RNG shape, so F1/C1/C2 share the realised query mask and cost-risk increment, including the same nominal-cost reference. Their betting strategies differ: F1 transfers a Brier-derived predictable stake to the cost increment; C1 uses discounted cost history; C2 uses cost-history ONS. All three use the registered theoretical log(1/.05) threshold. This supports within-repo parity of nominal label access, delay, cost-null target and threshold class. It does not make C1 or C2 a faithful reproduction of a particular published algorithm, and it does not independently prove conditional-null validity under arbitrary dependence or uncertain nominal risk.

C7a is `sr_cost_tight`. Its threshold is absent from `THEORY_THRESHOLD`, so the runner calls `harness.calibrate` on a separate 400-path cell-specific null simulation and uses the empirical 95th percentile of horizon maxima. This is a different threshold guarantee from F1/C1/C2 and the protocol marks it descriptive. In the stored 600-seed G5 panel its null false-alarm maximum is 0.061667 at 10% labels and 0.071667 at 20%; pooled benign false alarm is 0.081 and 0.112. Its harm power is higher than F1 by 0.190 and 0.132, respectively, but it is not a same-guarantee dominance result. Brier-null HG/ONS references target a different null and remain diagnostic.

The original D1 PASS is reproduced from stored seeds and remains the historical registered verdict. The stronger-in-sample comparator choice and its fixed-choice interval are examined separately in `33_H2C_COMPARATOR_SELECTION.md`. The Bernoulli query rate and synthetic estimated nominal reference are quantified in `35_H2C_G5_NOMINAL_AND_BUDGET.md`; the G5 result is not a hard-budget study. No simulation replay or published-source fidelity audit was performed here. Reviewer: lead, INTERNAL_ONLY; G03/G04 remain unsigned.
