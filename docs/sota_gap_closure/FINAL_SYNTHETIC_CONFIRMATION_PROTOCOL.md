# Final synthetic confirmation protocol (frozen BEFORE `scripts/gap/e15_confirm.py` is run)

**Not reused as untouched evidence:** G1 and G2 held-out pools of the previous phase, and every development world of this phase (seed blocks 1000-80000). The confirmation pools below use new generators' parameters and seed block **900000+** (null calibration streams for the classical detectors: 1,400,000+). Nothing here has been run when this file is committed.

## Frozen items
* **Algorithms and parameters:** `configs/gap_closure/frozen_confirmation_v1.json` (committed with this protocol): the arm list with every hyperparameter, label fraction, delay (5, or the stated delay model), alpha = 0.05.
* **Baseline tuning:** `pprm` and HG use their previous-phase settings (HG: discount .99, gate window 100); PH (delta .05) and CUSUM (slack .25) use the previous-phase values, with nominal mean / sd and the 95% null threshold estimated from an independent null stream of the same world family (400 paths). No baseline is re-tuned on confirmation data.
* **Data-generating assumptions:** G3 (K3 jump persistence .99: source/concept 2.5/benign covariate 2.5; K4 cycle persistence .985: cost FN=15/concept 1.6/prior 1.2; K2 null), G4 (reversal cycle kappa .35; K3 betas 1/.5/-.7 with GARCH a=.12 b=.84; null), G5 (concept 2.5 under six proxy modes; null with static proxy bias), G6 (concept 2.5 under uniform / geometric / outcome-dependent / heavy-tailed / burst delay; nulls: AR(.9, sd 1.3), cluster(120, sd 1.3), outcome-dependent delay). 400 seeds per harm world, 1000 per null world.
* **Primary metrics:** (1) power = P(alarm at or after the first harmful step | harmful step exists); (2) false-alarm rate (alarm before the first harmful step, or any alarm in a no-harm world); (3) cumulative harm before alarm. Practical effect threshold: |paired difference in power| >= 0.03, false-alarm difference >= 0.02.
* **Primary comparisons (exhaustive list, Holm-corrected together):** HG vs pprm; HG vs PH; HG vs CUSUM; each frozen fix vs its parent (fix arms listed in the config). Secondary (uncorrected, descriptive): per-world differences.
* **Statistical analysis:** paired differences per seed (all arms share worlds, seeds and query matrix); cluster bootstrap over worlds x seeds (4,000 resamples, resampling worlds first, then seeds within world), 95% percentile intervals; two-sided bootstrap p; Holm adjustment over the primary list (selection across the candidates considered during development is bounded by the fact that only the frozen shortlist is evaluated and no arm can be added after seeing results; the number of candidate fixes screened in development (3 fixes x 3 parents x variants) is the family size used for Holm).
* **Validity analysis:** null worlds only, Wilson 95% intervals; a method "meets validity" on a null world if the Wilson interval's lower bound is <= 0.05.
* **Computation:** repeated matched runs (5 repeats, same stream, same process) of the frozen arms on one confirmation world, run on an otherwise idle machine, after the statistical run (`FINAL_RUNTIME_RESULTS.md`).
* **No post-confirmation tuning:** if a frozen arm fails, it is reported as failed.

## Addendum: confirmation round 2 (frozen BEFORE running; `configs/gap_closure/frozen_confirmation_v2.json`)
After round 1 (run, analysed, not modified), the corrected-floor development reruns (S04 v2, S06 v2, S08 v2; all dev pools) produced candidates that round 1 does not contain: growth / growth-look / variance allocation with propensity floor frac/2, and info-value pacing under a hard cap. They are frozen in the v2 config and evaluated once on the **same confirmation pool parameters with fresh seeds (block 1,100,000)**. Round 2 arms: HG, HG with the pathwise cap (comparator), HG + growth / growth-look / variance allocation (floor frac/2), HG + info-value pacing (hard cap, floor frac/2), HG + robust mixture. Primary comparisons (Holm over the five): growth-floor vs HG, growth-look-floor vs HG, variance-floor vs HG, info-value-pace vs hard-cap HG, growth-look-floor vs variance-floor. Because non-uniform arms realise more labels at the same nominal fraction, the analysis also reports realised labels and the label-matched gain against the uniform power-versus-labels curve (HG at fractions .1 and .2); the nominal-fraction paired test alone is not accepted as evidence of a label-efficiency gain. Round 1 results are not reused as evidence for round 2 candidates.
