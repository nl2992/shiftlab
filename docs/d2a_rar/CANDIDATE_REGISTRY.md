# Candidate registry (WP5) - Drift2Act / RAR programme

Generated by `scripts/d2a_rar/build_candidate_registry.py` (grammar `1.0.0`); do not edit by hand. **These are candidate identities (structured hypotheses), not experiments and not results.** No candidate is declared novel: `prior_art_status` is inherited from `registry/prior_art.yaml` (a failed search is not proof of novelty); families the WP4 ledger did not cover are UNVERIFIED.

## 1. Grammar summary

An identity = `host x research_question x mechanism family x variant x target_null x discrete knobs`. Source of truth: `src/shiftlab/autoresearch/grammar.py` (types, hooks, rules, dedup, scoring) and `families.py` (24 Phase-5 families, one table row per variant).

- Hosts: `drift2act`, `rar`, `cost_aware_binary` (RAR harness mode), `challenger`, `contract_native`.
- Questions: Q1 gap-aware evidence, Q2 decision-valued labels / decisions, Q3 integration (J00/J10/J01/J11).
- Nulls: `cond`, `marg`, `absolute_risk`, `economic`, `none` (registry/null_assumptions.yaml classes).
- Knobs: small discrete sets; the first value is the default. `parent_id` = the default-config sibling (or `BASE-<host>` for the default itself); Q3 identities have `parent_ids` = [Q1 constituent, Q2 constituent].

Identity key: `candidate_id = CAND-` + 16 hex of `behavioural_signature` = sha256(`mechanism_signature`, config with inert knobs masked); `mechanism_signature` = sha256(canonical mechanism, host, question, null, hook, new-hypothesis text).

### Compatibility rules (enforced by `validate_identity`)

- Gate-2 mechanisms (`rar.gate2`) only on `rar`; Gate-3 only on `rar` or `cost_aware_binary`.
- A `request_size` mechanism only through the Drift2Act hook `d2a.request_size`; on Drift2Act every Q2 acquisition family must use it (it decides HOW MANY labels, never which index), so per-item propensity knobs are inert there (`propensity_score` masked).
- A mechanism needing gap-aware evidence must declare `target_null` in {cond, marg}.
- Each variant lists the hook per host it supports; the null must be allowed on the host (`HOST_ALLOWED_NULLS`) and declared by the variant; `scoring_null == target_null` always (a cond method is never scored on the marginal null).
- HIGH_OVERLAP / KNOWN prior-art status => `role = baseline_or_ablation_only` (or `narrow_residue_test` for the F4 VOQ-vs-certificate-state variants) and `novelty_bearing = false`.
- Q3 identities carry `blocked_until = 'Q1 and Q2 winners'`. Q3 is generated only on drift2act and contract_native (RAR has no Q1 evidence hook).
- A variant matching a `do_not_repeat_without` construction gets `blocked_by` (ledger id + requirement) unless a `new_mechanistic_hypothesis` is declared.
- Mandatory comparators: Q1 {Markov-LR, Sethi plug-in on thinned chain, fixed spacing, restart-without-gaps, conditional-null certifier, Page-CUSUM}; Q2 {uniform, pending cap, fixed schedule, front-loaded, Drift2Act native audit, ASI-inspired, Gong-Zhang paid-obs, PAVE}; RAR-gate candidates also unmodified RAR AND Cost-Aware Binary; Q3 {J00, J10, J01, Gong-Zhang adapted}; plus the WP4 comparators of the mapped family.

## 3. Prioritisation (transparent, deterministic)

`score = 0.30*prior_art + 0.25*failure_link + 0.15*host_strength + 0.15*simplicity + 0.15*null_eligibility - 0.03 (non-default knob combination)`. Components in [0,1]:

- `prior_art`: {'PLAUSIBLY_DISTINCT': 1.0, 'UNVERIFIED': 0.5, 'KNOWN': 0.1, 'HIGH_OVERLAP': 0.1}; narrow-residue variants (F4 VOQ vs certificate state, release survival, propensity-by-certificate-gap) 0.6. PLAUSIBLY_DISTINCT families (F5, F6 Gate-2 / recovery-gain, F7, F9) therefore rank first.
- `failure_link`: 1.0 if the family links a ledger row whose problem survives the null correction (`SURVIVING_FAILURES` = ['FL-009', 'FL-012', 'FL-021', 'FL-030', 'FL-031', 'FL-035', 'FL-036', 'FL-039', 'FL-043', 'FL-045', 'FL-052'], FAILURE_ATLAS_CORRECTED section 4), 0.5 if it links only closed/other rows, 0 if none.
- `host_strength`: {'drift2act': 1.0, 'rar': 1.0, 'cost_aware_binary': 0.7, 'contract_native': 0.6, 'challenger': 0.5} (Drift2Act and RAR are the primary hosts).
- `simplicity`: (6 - complexity level)/5; level = variant complexity + 1 when the hook is NOT_EXPOSED.
- `null_eligibility`: {'cond': 1.0, 'marg': 1.0, 'absolute_risk': 0.9, 'economic': 0.6, 'none': 0.3}.
- Blocked and Q3 identities are never selected. Weights are judgement calls, documented here, not tuned on any result.
