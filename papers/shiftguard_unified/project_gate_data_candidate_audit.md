# Project GATE public-use trial: candidate data audit

**Audit date:** 2026-10-26  
**Status:** archived copies of the publisher's public-use archives were acquired and audited at the aggregate/schema level on 2026-10-26. Policy evaluation has not been run.

## What the sources establish

The U.S. Department of Labor describes Project GATE as a random-assignment demonstration in which 4,198 applicants were assigned to an offer of entrepreneurship services or control. The public-use collection contains application data and survey follow-ups around 6, 18, and 60 months. The data guide identifies `application.sas7bdat`, `wave1.sas7bdat`, `wave2.sas7bdat`, and `wave3.sas7bdat`; the application file includes `treatment` and `date_random_assignment`. The DOL final evaluation report explains that one person found to be non-randomly assigned was removed from the analysis, accounting for the 4,197 records in the public-use analysis file. It also excluded 120 people in mixed-arm business partnerships to limit spillover, leaving an analysis sample of 4,078; the public-use application schema has no partnership identifiers or analysis weights, so those exclusions cannot be reconstructed exactly. The report also estimates program cost at $1,321 per program-group member from invoices, although the dollar year needs verification before combining with monetary outcomes. [DOL dataset description](https://www.dol.gov/agencies/eta/reports/project-gate-dataset) · [DOL public-use data guide](https://www.dol.gov/sites/dolgov/files/ETA/reports/pdfs/Project%20GATE%20Public%20Use%20Dataset.pdf) · [DOL final evaluation report](https://www.dol.gov/sites/dolgov/files/ETA/publications/Growing%20America%20through%20Entrepreneurship%20-%20Final%20Evaluation%20of%20Project%20GATE.pdf) · [Data.gov record](https://catalog.data.gov/dataset/project-gate-growing-america-through-entrepreneurship-final-evaluation-dataset?from_hint=eyJxIjoiR2F0ZSJ9)

The archive copies were recovered using the DOL file URLs found in an Internet Archive capture of the DOL landing page because direct DOL downloads returned HTTP 403. Their SHA-256 hashes are `C25BA81923888A004641356358200B7F04F59E4F1D13A83D0F2FE384ED6AF721` (`SASDataset.zip`) and `F7B200DB081828267DA775B00074F557844BF76664B5EE3F9AC758E817CA8547` (`ProjectGate.zip`); ZIP CRC checks pass and duplicate SAS members match across both archives. Raw archives are in the ignored local `data/raw/project_gate/` directory. The aggregate-only audit is reproducible with `uv run --with pyreadstat python scripts/audit_project_gate_source.py`; it writes `data/reports/project_gate_source_audit.json` and no participant-level rows.

The audit reads 4,197 application records, 3,449 wave-1 records, 3,038 wave-2 records, and 2,450 wave-3 records. `gateid` is unique in the application file and each wave, with every wave ID matching an application ID. The public-use cohort has 2,103 control and 2,094 treatment members; assignment dates span 2003-09-24 through 2005-07-11. The DOL report states a 50% probability for each arm and assignment less than one week after application on average, supporting eligible application fields as baseline covariates. Follow-up completion flags agree exactly with linked IDs. Response rates for control/treatment are 80.4%/84.0% at wave 1, 70.1%/74.6% at wave 2, and 55.9%/60.8% at wave 3. The wave-3 codebook defines `dwkc_a` as current self-employment (`0=No`, `1=Yes`); all 2,450 wave-3 records have one of those values. Interview dates are 1,375–2,101 days after random assignment (median 1,706 days), but label-release time is not recorded. The parser's system-missing count does not treat codebook-coded legitimate skips, don't-knows or refusals as missing; these need field-specific recoding. For `dwkc_a`, worst-case missing-outcome bounds over the public-use cohort span **−42.0 to +41.2 percentage points**. They omit sampling uncertainty and the published mixed-partnership exclusion/weighting, so they do not give a no-interference ITT bound. The response gap and missing partnership data make population policy values sensitive to assumptions.

## Fit for ShiftLab

This is a fixed-horizon randomized offer task. A learner could use eligible pre-assignment application features to target offers and evaluate a prespecified policy on disjoint participants using the documented 0.5 assignment probability and an outcome-specific off-policy estimator. The W3 `dwkc_a` endpoint is a well-defined binary interview-time outcome, but is measured at differing intervals and observed for only 58.4% of the public-use cohort. DOL supplies an average intervention cost ($1,321 per program-group member), not an individualized cost schedule or a verified dollar-year. Survey waves are not a sequential-monitoring task: interview measurement dates do not establish label-release times. Differential wave response requires a preregistered adjustment and sensitivity analysis. The missing mixed-arm partnership identifiers prevent exact replication of DOL's no-contamination analysis population and weights.

## Access and decision

The Data.gov catalog classifies the record as public and reports `rights: TRUE`; this metadata does not itself establish a redistribution license. Direct DOL downloads returned HTTP 403 in this environment, so files were recovered from an archived capture of DOL's own download links. Raw archives remain ignored by Git. The candidate is locally acquired and schema-audited, but **has not been used for policy evaluation**.

**Decision:** retain as a fixed-horizon development candidate for outcome-specific policy evaluation, subject to explicit missingness and interference contracts. W3 current self-employment (`dwkc_a`) is a candidate endpoint for evaluating targeted program offers, not adaptive model deployment. DOL's average cost can inform a cost sensitivity, but not an individualized net-utility claim until the cost period and outcome units are aligned. Before fitting policies, freeze a development split and response sensitivity plan; do not treat the complete-case estimate as a population effect or use this source for sequential-feedback claims. The codebook review and aggregate response/timing/bounds are in `real_data_task_contracts.md` and `data/reports/project_gate_source_audit.json`.
