## 2. Native problem and estimand

- Setup (Sec. 2, p.2): base predictor f-hat, thresholded decision mechanism f_psi(x) = g(f-hat(x), psi)
  (Eq. 1), bounded loss l in [0,1], risk R(psi) = E_P[l(f_psi(x), y)] (Eq. 2). Stream: at each t see x_t,
  decide, then y_t is revealed and loss z_t measured; "covariate -> decision -> label -> loss" (p.2).
  Shift: (x_t, y_t) ~ P_t, arbitrary, unknown, possibly dependent over time (p.3, Remark p.15).
- Estimand: for each candidate threshold psi in a grid, the instantaneous conditional risk E[z_t | F_{t-1}]
  against a user risk level eps in (0,1).
- Null, Eq. 3 (p.3): H0(psi): E_{P_t}[z_t | F_{t-1}] <= eps for all t (risk controlled); H1: exists t with
  E[z_t | F_{t-1}] > eps. Filtration (p.3, App. A.1 p.14): F_{t-1} = sigma((z_1,pi_1),...,(z_{t-1},pi_{t-1})),
  i.e. generated by past losses and forecasts, F_0 trivial. Direction is one-sided (upward risk).
- Feedback regime: the loss z_t must be observed every round, immediately after the decision. No missing,
  delayed, or selectively sampled labels are treated (UNVERIFIED by absence in Sec. 2-6; the batching
  discussion p.7 changes sample count per step but not label availability).
- Multi-stream output: the psi-CS, C_t = {psi : M_t(psi) < 1/delta} (Eq. 5, p.4), the thresholds not yet
  rejected. Size of C_t shrinking to zero is read as "a model update is required" (p.4). Model updating
  is explicitly left to future work (p.4).

## 3. Exact algorithm

For each psi in grid (code: 0 to 1 step 0.01, `cfg_exp.py:67-70`):

1. Loss z_t(psi) in [0,1] (Sec. 6.1: FP/FN indicator loss for outlier thresholding; Sec. 6.2: miscoverage
   indicator for set prediction). Risk level eps and confidence delta (defaults 0.1 and 0.1, p.7,
   `cfg_exp.py:57-59`).
2. Wealth process, Eq. 4 (p.3-4): M_t(psi) = prod_{i<=t} (1 + lambda_i (z_i - eps)), M_0 = 1,
   lambda_t predictable, lambda_t in [0, 1/eps) (Lemma 4.1 proof, p.15).
3. Alarm / rejection of psi: first t with M_t(psi) >= 1/delta (Lemma 4.2, p.5; code
   `EProcessTracker.check_stop_time` lines 235-250 records the first crossing; the process continues).
4. Betting rate, the AGR closed form (Sec. 6, p.7, displayed equation just after "Choice of betting rate"):
   lambda_t^AGR = max{0, min{ (mu-hat_{t-1} - eps) / (sigma-hat^2_{t-1} + (mu-hat_{t-1} - eps)^2), (1/2)/eps }},
   with mu-hat, sigma-hat^2 the running mean and variance of {z_i}_{i<t}. Truncation constant c=1/2 (code
   `tracker_ood.py:197-199`, `bet = max(0, min(term, c/eps))`, c=0.5). Confirmed on the rendered page.
   Jitter 1e-10 added to mu, var and term in code (lines 195-198) is not in the paper. Variance is torch
   `.var()` (unbiased) over `losses[ts_start:ts]` (line 196); slice excludes the current step so the bet is
   predictable. Alternatives in code: `unit_bet` (lambda=1) and `grapa` (line 201-207: argmax over
   lam in arange(0.1, 1/eps, 0.1) of the mean past log-growth; the paper cites "root-finding over a fine
   grid" (App. C, p.19) and the GRO definition (Def. 4.4, p.5: lambda_t = argmax over [0,1/eps) of E_H1[log M_t])).
5. Burn-in (p.7): t_burn = floor(100/B) steps with no betting (zero bet; code lines 212-213,
   `NR_BURNIN=100`, `burn_in = int(NR_BURNIN / BATCH_TIMESTEP)`, line 168). Only the true-risk tracker skips it.
6. Sliding window S (p.7): bets use only the last S losses (`ts_start = max(ts - window, 0)`,
   lines 188-189 and 195); the product M_t itself is over the whole history. Window 0 = full history
   (`TRACKER_WINDOW = [0,0,0]`, `cfg_exp.py:81`). The paper's commands include windows 0, 10, 50, 200 with
   batch sizes 1, 10, 50 (`commands.txt`; main text uses S=50, 365 for the shown figures).
7. Batching (App. C, p.19): with B samples per step the factor is the arithmetic mean over the batch:
   M_t = prod_i (1/B) sum_b (1 + lambda_i (z_{i,b} - eps)); code `get_evalues(..., reduction="mean")`
   lines 217-226, 437.
8. Output: stopping time tau(psi), detection delay tau(psi) - tau*(psi) where tau* is the oracle first time
   the true batch-estimated risk (B*=1000 samples, p.6) crosses eps (code: point-risk tracker uses a
   consecutive-violation counter `STOP_COUNTER[0]=5`, lines 51-72), false alarm if delay < 0
   (`get_detection_delay_false_alarm`, exp_ood.py:182-189). psi selection (code `psi_select="min"`,
   exp_ood.py:480-482) is a convenience; the paper gives no guarantee for it (p.4 "Practical considerations").
- Comparison trackers (p.6-7): oracle point risk, running risk R-hat_r, summation process
  M^SUM = sum lambda_i (z_i - eps) (Sec. 3, p.3; valid but less efficient), predictably-mixed
  Empirical-Bernstein process M^EB (App. C p.19, from Waudby-Smith and Ramdas 2024 Thm 2, c=1/2).
- Reverse hypotheses under i.i.d. P_0 (Sec. 3.1, App. A.3 p.15): reversed wealth prod(1 + lambda(eps - z))
  certifies risk control forever. Not applicable under shift (p.5).
- Rolling risk control reinterpretation (Sec. 3.1, p.4): Feldman et al. 2023 update psi_t = psi_{t-1} + gamma(z_{t-1} - eps)
  is treated as the summation wealth process (asymptotic, not finite-sample).

## 5. Guarantee

- Lemma 4.1 (p.5, proof p.15): under H0 with predictable lambda_t in [0, 1/eps), M_t is a test supermartingale.
  Uses only boundedness of z in [0,1], eps in (0,1), and E[z_t - eps | F_{t-1}] <= 0.
- Lemma 4.2 (p.5, proof p.15-16 via Ville): P(exists t: M_t >= 1/delta) <= delta under H0, for each fixed psi,
  across time. **Not across thresholds at a given time** (p.4: no multiplicity correction; psi selection is
  not covered).
- Lemma 4.3 (p.5, proof p.16-17): asymptotic consistency (power one) if risk exceeds eps from some time
  with a positive margin; proof uses a Taylor approximation log(1+x) ~ x and assumes bounded betting rate
  (loose proof, App. A.4).
- Def. 4.4 (p.5): GRO bet. Prop. 4.5 (p.6, proof p.17-18): detection delay ~ O((log(1/delta) + T)/(lambda mu)),
  "approximately", for a stylised step-change setting, derived via the summation process.
- What it does not cover: delayed/missing/propensity-selected losses; paired or relative risk; unbounded
  losses; adaptive choice among thresholds; any claim about the practical delay of the AGR bet beyond the
  heuristic Prop. 4.5; any "harm relative to a reference" quantity (the target is absolute risk of one
  threshold rule against a fixed eps).
- Assumptions on shift: none; dependence over time allowed provided the conditional-mean null holds
  given F_{t-1} (Remark, p.15). Because F_{t-1} contains only losses and forecasts, a covariate-dependent
  predictable bet is not part of the paper's statement (the filtration would need to be enlarged;
  standard but not stated, UNVERIFIED).

## 6. Mapping to ShiftLab's deployment contract; achievable tier

Contract: two frozen models, paired loss Z_t = c(dep) - c(ref) in [-5,5], hard budget B=200, query cost
0.05, switch cost 5, delayed labels (`scripts/sota_sprint/bench.py:25`, `interface.py`, `interface_v2.py`).

- Native fit is closer than for WATCH: Timans is an eventwise conditional-mean e-process with a one-sided
  null on a bounded scalar. Setting z_t = (Z_t / (2C)) + 1/2 with C=5 and eps = 1/2 turns the paired
  excess-cost null E[Z_t | F_{t-1}] <= 0 into Eq. 3 exactly, since z in [0,1] and eps in (0,1). This map is a
  ShiftLab construction (the paper never pairs). It is already what the repo's `_timans_logs` does per
  `docs/hgxh2c/01_BASELINE_AUDIT.md` section 3 (score = 0.5 + 0.5 Z/B, eps = 0.5; recorded replay error 0.0
  and 1.86e-7 vs the official PyTorch tracker; documented as not re-run in that audit, and not re-run by me).
- Gaps to the contract: (i) labels are not observed every round: querying is budgeted and labels delayed;
  the paper's Lemma 4.1 needs z_t observed and the bet predictable w.r.t. what is observed. Skipping
  unqueried rounds (multiplying by 1) preserves validity only if the query decision does not depend on the
  unseen outcome; with a propensity-dependent query rule, an IPW or prediction-powered increment is needed
  (not in the paper; the hgxh2c "PP increment" variant is a ShiftLab/Csillag construction). (ii) delayed
  labels reorder the e-process updates; validity needs a filtration indexed by release time (UNVERIFIED
  for the Timans proof). (iii) The psi-grid and psi-CS have no counterpart: ShiftLab has a single
  deployed-versus-reference comparison, so only one wealth process runs. (iv) Windowed bets (S) are allowed
  and valid because predictable.
- Honest rollback: alarm of the e-process on paired excess cost -> switch to the reference model, paying cost
  5. This is a legitimate use of the test (it tests harm vs the reference), but the paper gives no switching
  rule, so the switch is a ShiftLab adaptation (T3). Detection delay is the operative performance, not Prop. 4.5.
- Tiers: **T1** for the scalar wealth rule is already shown by the repo's replay verification (claimed);
  independent re-run would be needed before relying on it. **T2**: Eq. 3-4, lambda^AGR from printed equation
  and p.7 formula, feasible without code (done in effect). **T3**: anything with query budget, delay, PP/IPW
  increments, or switching. Named "Timans" only for the full-observation scalar rule; the budgeted PP versions
  are T3 and must be labelled "Timans-style".

## 8. Reproduction identities and paper-stated facts

- If z_t == eps for all t, every factor is 1 and M_t == 1 (Eq. 4).
- Lemma 4.2 with delta = 0.1: under i.i.d. z with mean <= eps, simulated P(max_t M_t >= 10) <= 0.1.
- AGR identities: constant z = c0 > eps gives variance 0 so term = 1/(c0 - eps), capped at 0.5/eps; z with
  mean <= eps gives lambda = 0 (max with 0).
- Burn-in: lambda == 0 for t < floor(100/B); at B=1 wealth is exactly 1 for the first 100 steps (code lines 212-213).
- Grid grid: lam in {0.1,...,1.9} for eps=0.5 (upstream `arange`, line 202).
- Paper-stated qualitative results (not numbers): running risk shows false alarms for small windows; M_t has the lowest
  delay among trackers with false-alarm control; psi-CS shrinks to zero under stepwise shift (p.7-8). Numeric
  tables are in the supplement (pp.21-23); not transcribed (UNVERIFIED). The hgxh2c native run (3 trials on
  `exp_uci`, `docs/hgxh2c/02_NATIVE_REPRODUCTION.md`) found no paper numbers to compare.
